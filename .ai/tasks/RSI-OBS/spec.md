# 可追溯的 SPEC 审查与交付证据

## Delivery Contract

### Source

Issue #31 与本任务登记的 [source.md](source.md)。

### Outcome

维护者可以用一次任务级分析复核需求发现、修订、验证与交付执行结果，提高缺证和冲突的可见性。

### Boundary

可观察范围由已落盘的记录和独立执行结果确定。模型质量及因果收益需要另外的对照实验。

### Oracle

实际调用受控任务的审查、状态推进、最终验证与 RSI 分析工具，运行订单导出断言，检查结果和引用文件。

### AC mapping

审查与修订链由 AC-001、AC-002 验收。Oracle 证据由 AC-003 验收。证据健康、成本和兼容性由 AC-004、AC-005 验收。

## Acceptance Criteria

- AC-001: 任务分析输出可复核的审查轮次和 Finding 生命周期，并报告取消、失败、运行中、损坏、跨任务或断链的证据。
- AC-002: 发现与来源、Spec/AC 修改、阶段快照及最终验证按实际标识和版本关联，信息不足时标为 unlinked。
- AC-003: 与已登记版本匹配的独立前台 Oracle 执行可得到 proven 或 failed，只有流程裁决或作者执行时保持 unverified。
- AC-004: 记录缺失或截断与已观测耗时、轮次及 Token 用量可在分析中复核，重复查询按原始标识去重并保持任务状态。
- AC-005: 受控正反例覆盖输出、真实 ToolRuntime 接线、历史兼容及现有 verify 回归，提交经检查的复跑说明与 JSON 样例。

## Requirements

读取原有 Review 文件和状态链接，保留各轮身份、指纹、声明来源、回应及复审结论。证据路径可回到原记录。

## Design

任务查询聚合原有审查和最终验证。为最终验证保存已有审查引用。采集工具的结构化退出码，并通过验证者的会话归属、命令及调用 ID 确认 Oracle 结果。所有可观测结论来自已保存的数据。

## Areas of concern

来源真实性属于登记方。历史验证缺少审查引用、Oracle 仅有散文描述以及无法确认独立执行时都保留不确定性。原始会话与代码快照使用本地 RSI 目录。
