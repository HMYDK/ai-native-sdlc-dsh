# 复审完成率对照（2026-11-19）

用户在首轮结果及下一步说明后明确回复“继续”，授权本轮继续验证。最多 4 次 reviewer activation，不自动重派，原第一轮 4 次记录保留。

## 事前设计

本轮唯一显式模型配置变化是 reasoningEffort：high → low。已从本机 DSH 0.2.2-rc.3 适配器确认支持 off/low/high/max，low 仍启用 thinking。保持同一安装 tarball、模型 deepseek-v4-pro、工具入口与提示词；每轮 8 分钟、观察用量 80000 tokens、12 步限制不变。首两项保持各自上轮的输出上限（8192 / 16384）。

1. 重放 SR-BUILD 修订复审：原始来源、当前修订 Spec、Intent、前轮 completed 记录和逐项回应均复制自首轮。预期逐项 addressed，依据是补回构建 O-2、AC-005/006、Oracle 和允许必要依赖。
2. 重放 SR-LOCAL 反证复审：Source/Spec 不变，前轮发现和作者反证原样保留。首先检查能否产出完整逐项结论；withdrawn/open/needs_clarification 均须核对理由，不预设争议一定撤回。
3. 干净正例 SR-LOCAL-V2：使用上一轮 next-inputs 已准备的有限域材料；预期无新增发现，不要求集合外输入或完整构建。输出上限 8192。
4. SR-NOFIX：使用真实首轮构建发现，但恢复首轮有缺陷 Spec；作者虚假声称已补 O-2/AC-005/006。预期保持 open，不能凭作者声称关闭。故意错误的回应只用于这个受控案例。输出上限 8192。

在独立临时工作区只放必要任务文件和显式关联的前轮记录；不放标签、其他失败调用、RSI 历史或修订预案。首两项的插件待审 prompt 应与原失败调用逐字相同，运行后核对哈希；会话工作区路径和历史文件环境不同，因此不宣称完全同环境随机对照。此处的隔离是评测材料控制，不是新产品行为。

输入文件哈希见 input-hashes.json，虚假修订回应见 nofix-response.json。原始依据/标签仍由实现者准备，非独立盲评；逐例读数不得外推总体效果。若前两项仍不能完成，优先停止剩余调用并定位，不用正例掩盖关键复审失败。

## 第 3 次调用前调整

第 1 次在 low / 8192 下完成并有依据地 addressed。第 2 次在 low / 16384 下以 MALFORMED_RESPONSE 结束：structured_output 的参数共 2121 字符 / 4391 UTF-8 字节，末尾 JSON 数组未闭合；它不是本次的输出 token 上限截断，也不计为有效复审。插件待审 prompt 与首轮相应失败调用逐字相同，原失败保留。

据此先在现有提示词增加“summary 一两句、follow_up 每项一至三句证据、避免重抄材料、及时提交完整数组”的撰写要求，保留原有审查与逐项覆盖规则。全量程序回归和新 tarball 安装后，第 3 次用于相同反证复审的人工重放；第 4 次仍检查未修却声称已修的负例。干净正例本轮暂不派发，不追加第 5 次行为试验。第 3 次与第 2 次的显式变化为提示词撰写要求；它是单例排障，不能据此建立稳定的因果改善结论。

## 第 4 次调用前调整

第 3 次在累计报告 94,798 tokens 后，模型发出了 JSON 可解析的 structured_output 调用；但评测脚本在 assistant/message 到达时立即 abort，将本可零额外模型调用提交的结果也取消了。工具返回 ABORTED、任务记录 cancelled，不能算作有效复审。这个失败由评测器的预算处理导致。

修正评测器：超预算响应若只请求一次 structured_output，允许其执行；下一 step/start 仍检查用量并取消，防止结构化工具拒绝后继续调用模型。混合其他工具或自由文本仍取消。新增三个离线回归检查覆盖这一条件，产品插件不放宽解析规则。

第 4 次改为相同反证复审重放，仍 low / 16384、相同产品 tarball 和待审材料；换干净工作区只保留原始 completed 前轮。未修反例本轮不执行，原材料留待后续。累计调用数仍为 4，既有失败全部保留。
