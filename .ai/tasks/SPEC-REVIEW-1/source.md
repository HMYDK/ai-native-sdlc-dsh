# 本任务的需求依据

来源：2026-11-17 本仓库的用户对话。以下保留用户原话，并将协商后的实施范围单独列出，不冒充用户逐字原文。

## 用户原话

> “SPEC 前置审查” 解决的是什么问题？回答我

在明确其目标为“开工前发现需求到 Spec / AC 转换中的遗漏、误解与范围偏移”后，用户回复：

> 你说的没错。所以你准备怎么落地呢

随后用户要求复核方案是否偏离目标，并要求给出落地计划与全流程图。最终在完整方案展示后回复：

> 那现在是不是可以开始动工了？

## 对话中形成并据此开始实施的范围

- 新增 SPEC 阶段独立审查，对照原始需求报告遗漏、范围偏移、验收反例与必要澄清。
- 作者修订或提供反证，复审确认修订、撤回错误发现或保留实质争议。
- 首版作为建议执行的纠偏流程，不新增强制推进门禁；最终交付验证保持独立。
- 原始依据与作者推断分开；缺失来源、无效输出和输入变化不能当作没有发现。
- 保存输入版本、审查发现、回应和复审结果；真实模型行为测试需要单独预算，既有 Phase 2 / B1 未获本轮执行授权。

这是本次对话的范围整理；它不声称 SPEC 审查能证明需求穷尽完整，也不宣称模型效果已验证。

## 后续执行授权（2026-11-18 至 19）

在提出最多 4 次真实模型小样本试验后，用户原话：

> 继续  直到你认为需要停下来为止

首轮报告两次复审输出截断，并说明下一步集中验证预算内的复审完成率后，用户回复：

> 继续

本任务据此继续进行有界 SPEC 试验，并如实保留首轮失败及后续对照。这里的“继续”不改写原始产品目标，也不授权把受控样例结果外推成普遍质量保证；既有独立 Phase 2 / B1 没有执行。

## 反向检查与交付核验的继续授权（2026-11-19）

在报告修订确认与反证撤回已取得有效结果，同时说明尚缺干净正例、未修反例和独立交付验收后，用户回复：

> 继续

本轮准备材料期间用户再次回复“继续”，继续指向同一项工作，不另行增加本轮最多四次模型派发的预算。两个 SPEC 案例之后，独立交付核验使用任务已登记的全部验收标准；原本的建议性产品边界不变。
