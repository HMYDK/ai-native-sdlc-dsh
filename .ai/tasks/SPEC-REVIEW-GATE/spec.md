# Spec

## Delivery Contract

### Source
Issue #29 及当前实施授权，见 source.md。

### Outcome
- O-1: 任意受支持的前进操作都只能使用当前资料的有效审查，且没有未解决的 Finding。
- O-2: 输入不变时复用同一审查，允许回到 SPEC 修订及历史任务补审，旧交付证据完整保留。

### Boundary
覆盖 SDLC 任务推进和任务模式验证。分支保护、任意文件写权限、来源认证和可信人工豁免在当前工具范围之外。

### Oracle
相同受控夹具对照建议版和门禁版的推进结果，通过真实 ToolRuntime 验证拒绝、逐项收口和后续交付，打包后在隔离 DSH 宿主验证接线。

### AC mapping
- O-1 对应 AC-001、AC-002、AC-003、AC-005。
- O-2 对应 AC-004、AC-006。

## Acceptance Criteria
- AC-001: 所有工具的向前推进到 PLANNED 及以后阶段都核对 SPEC 审查，直接跳阶段无法省略。
- AC-002: 原文及澄清清单、Intent、Spec 和 AC 都与同任务已完成的审查记录匹配，缺失、损坏、失败、跨任务或过期记录不能推进。
- AC-003: 只有关联的独立复审可以关闭旧发现，未解决项、真实歧义和作者声明无法放行。
- AC-004: 输入未变时复用有效审查而不重新派发，支持退回 SPEC 和历史任务补审，保留既有验收、验证与完成规则。
- AC-005: 失败的阶段迁移不改变状态、登记或历史，任务模式验证也拒绝缺少有效审查的状态。文档列明任意文件修改的信任边界。
- AC-006: 旧版对照与当前受控验证可复核，全量 verify 与隔离安装检查通过，评测不发起付费请求。

## Requirements
登记任务原始文件和可选完整来源清单。完成审查后由工具选择链尾，变更任何登记输入时重新核对。

## Design
推进和任务验证共用一个审查读取与核对入口。状态只保存审查引用及记录指纹，输出继续使用现有 Finding 协议。单一历史审查链需要显式补审才可使用。

## Areas of concern
旧规则下分叉的审查、来源不可信、审查生成失败导致实际工作停滞，以及模型反馈的语义正确性。
