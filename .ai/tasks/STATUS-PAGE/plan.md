## Risks

- 🔴 **翻页顺序依赖 `scanTasks` 的排序——而它的首键是随时间变的。**
  我原来的论证是错的：我只查了比较器末尾的 `localeCompare` 兜底，
  **漏掉了首键"停滞分组"会随 now 变化**。独立验证者用 3 个任务、
  0.5 秒间隔实测出重复+漏任务。

  修法（已实现）：切窗按**与时间无关**的 task id 字典序，页内仍按
  `scanTasks` 的顺序呈现。缓解：两条测试**改变输入顺序**（模拟时间重排）
  并断言切窗结果一致——我原来那条"钉子"只对同一数组重调纯函数，
  看不见 `scanTasks` 层的重排，**证明不了它声称的东西**。

- 🟡 **`tasks` 的语义变了，但小仓库里看不出来。**
  ≤50 个任务时 `tasks` 就等于全部，所以这个变化在开发者的本地仓库里
  **天然测不到**。缓解：冒烟必须造 >50 个任务；Unit 层 `selectTasks`
  直接按窗口断言，不依赖"看起来一样"。

- 🟡 **输出 schema 是严格校验的**（`additionalProperties: false`）。
  漏声明一个字段会让**整个工具调用失败**。缓解：
  加完字段立刻跑冒烟（它真的 dispatch 工具，会暴露 schema 不匹配）。

- 🟡 **默认路径必须逐字不变（R1）**。最容易犯的错是"顺手统一了格式"，
  比如把 `note` 也放进默认路径。缓解：冒烟里断言默认调用的输出
  **不含**新增的窗口说明行。

  ⚠️ **这条风险真的发生了。** 我实现时把冒烟断言改成了相反的结论
  （"默认路径应当产生 note，因为它更可操作"），等于把 R1 的承诺悄悄改掉。
  独立验证者用 HEAD 的旧代码逐字对比证明：空仓库会渲染出
  「没有更多了：offset=0 已越过总数 0」。教训：**发现计划里的断言"不好走"时，
  不是改断言，而是回头看承诺是否真的做不到**。

- 🟢 `task_id` 不存在时抛错——这个语义与"返回空列表"不同，
  需要在错误信息里带上扫描根路径（Areas of concern 第四条）。

## Proof

对应 spec 的每条 Requirement，逐条给出可复核的证据：

| 要求 | 证据（要跑的命令 + 预期观察） |
|---|---|
| **R1 向后兼容** | 冒烟断言：不传新参数时 `note === undefined`（渲染不含窗口说明行）、`tasks` 与改动前一致。**另加一条空看板的渲染逐字比对**（`"没有任务。\n"`）——独立验证者指出这条曾经漏掉，而它正是本仓库开局的状态 |
| **R2 分页不重不漏** | 单测：30 个任务、页大小 10 → 3 页，各页并集 == 全部且两两交集为空。另加一条钉子：同一输入连续两次 `selectTasks` 输出顺序完全相同 |
| **R3 offset 超出** | 单测断言**结构化事实**（`entries` 为空、`start` 如实、`remaining === 0`、`complete === false`——空窗口不算看全）；给人看的「没有更多了」那句话由**冒烟**在真实渲染文本上断言（文案已移到工具层） |
| **R4 单任务详情** | 单测：`taskId` 命中 → 长度 1；`taskId` + `offset` → 仍长度 1 且 `note` 说明忽略了 offset；`taskId` 未命中 → **抛错**（`assert.throws`） |
| **R5 limit 夹到上限** | 单测：`limit = 1000` → 实际 200 且 `note` 含"请求 1000" |
| **R6 纯函数可单测** | `selectTasks` 的测试**不 import 任何 DSH 东西**，直接 `import { selectTasks } from './scan.js'`。单测条数从当前 38 增加到 38+N |
| **R7 仍然只读** | 冒烟里已有的只读断言（调用前后整个文件树 + mtime 完全一致）继续通过；新增的两条用例也要在同一断言范围内 |

**外加两条我自己加的**（spec 的 Areas of concern 要求）：

- 参数非法（`offset = -1`、`offset = 1.5`、`limit = 0`）→ 工具返回 `isError`，
  **且错误信息说明是哪个参数不对**
- `make check`（测试场端到端，真实仓库 + 真实 fs）继续 22/22——
  它是唯一覆盖四个插件接线的东西
