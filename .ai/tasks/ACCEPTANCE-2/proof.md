## 缺陷与修复依据

旧版的任务验证和完成准入共同相信调用方提供的 criteria，缺少独立于调用参数的完整清单。真实 Cordis、ToolRuntime、LocalFileSystem 和临时 Git 仓库中，Spec 三项而只提交一项仍可进入 DONE。第一次验证前改 Spec 也可作为新起点。它们是可重复的程序缺陷，不是已发生真实业务事故的证据。

现在从 Spec 登记完整清单、稳定 ID 和全文件指纹；跳阶段执行相同准入，issue 工具的退回同样检查；验证与 checkApproval 各自读当前登记和制品，不能靠绕过验证入口通过完成检查。历史裁决原样归档，不重新解释原编号。
