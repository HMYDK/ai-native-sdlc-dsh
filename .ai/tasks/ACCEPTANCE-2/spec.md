# 任务完整验收要求

## Requirements
用户已确认本方案及三个补充边界：跳阶段不能绕开登记；第一次验证前也核对已登记 Spec；稳定编号兼容历史内容哈希编号。

## Acceptance Criteria
- AC-001: Spec 必须显式声明唯一且非空的验收项，解析歧义必须报错，不能静默丢项。
- AC-002: 首次从 INTENT 或 SPEC 进入 PLANNED 及后续任意阶段时登记完整清单和整个 Spec 的指纹，跳阶段不能绕过。
- AC-003: 第一次和后续任务验证都核对登记的 Spec 指纹；说明文字修改也须退回 SPEC 重新登记。
- AC-004: 任务验证自动使用全部登记项，调用方缺项、改写、重复或替换时在派发前拒绝；额外检查只可追加。
- AC-005: 状态机及完成准入独立核对登记版本和完整结果，遗漏、重复、未知 ID、无证据及未满足项都不能完成任务。
- AC-006: 验证期间和验证后修改内容会使裁决失效；沿用 AC ID 重新登记也不能复用旧裁决。
- AC-007: 历史裁决和问题保留原始哈希编号，再次验证须补登记，历史问题仍须明确处理与复验。
- AC-008: 验证入口、完成准入和看板共用验收契约模块，看板准确显示应验数量和缺失项。
- AC-009: 双侧回归能复现旧版缺陷，修复版拦住坏结果且允许完整结果完成；真实打包副本可加载和执行工具。

## Design
共享 acceptance 模块负责章节解析、登记校验、覆盖核对及看板摘要。任务状态保存登记，schema_version 3 验证记录保存登记副本及独立内容快照；旧记录继续按原编号读取。

## Areas of concern
全文件指纹的成本是说明文字也需重新登记。登记代表采用这版规格，不代表人类审批。Git 文件可手工改写；插件不能保证最初的需求写全，也不能保证模型证据真实。
