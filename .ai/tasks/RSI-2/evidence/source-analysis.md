# 从真实任务得到的插件问题

来源任务 DEMO-22149；本次版本对照以 7955ddd / 0.3.1 为基线，不把它冒充为补录得到的历史运行指纹。`source-facts.json` 仅保留经过筛选的数值，不包含业务源码、工具正文或凭据。

六次验证依次是五次 reject、一次 approve。六次都完成了裁决，但 RSI 的实际配置数和工具结果数全部为 0，capture.errors 仍为空；代码快照六次均不完整。这些数值支持“记录有缺陷”，不能推出业务修复无效，也不能把五次 reject 本身当成插件缺陷。

根因有三处：作者和验证者属于兄弟 preset，原来的普通监听器收不到验证者事件；工作目录是多仓库的父目录，单 Git 根假设不成立；分析只检查 finished，没有检查执行证据。因此完成率会掩盖记录缺失。

修复使用全局事件观察，但只接收已登记会话；再用 DSH sessionQuery 核对完整日志，补漏并标明查询失败。代码快照按工作区内的仓库保存。任务关联作者、验证者和任务阶段，业务完成与记录完整分开。

可证伪检查见 `tools/bench/case-rsi-scope.mjs`：同一份真实 Cordis/ToolRuntime/LocalFS 夹具，旧版四项不满足，新版四项满足。它证明记录机制修复，不证明模型推理质量或业务任务耗时普遍改善。

0.4.0 已实现任务记录、证据提案、普通改进任务、版本对照与采用后反馈，看板显示记录是否完整。最终验证为 build + 单测 222 条 + 看板 host 26 条 + 9 个冒烟脚本 437 条，四个版本对照均成立。独立审查发现的问题已修复并复查；最终 tarball 已在隔离 profile 安装、逐文件核对并启动验证。交付范围和证据见 ../proof.md；用户 desktop profile 没有升级，也未声称真实任务质量已普遍提高。
