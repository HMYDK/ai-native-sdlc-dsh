# 验收标准
- R1：每条验收标准有稳定编号，完整且不重复的结果才可作为 approve；缺失、未知编号、损坏结果不能作为完成依据。原始模型结论保留。
- R2：问题处理明确记录来源、处理人、目标阶段、原因和证据；需要返工时阶段和处理动作一起提交；提交复验与实际复验通过分开。直接重新调用 verify 不能跳过上轮处理检查。
- R3：验证结论绑定代码/标准版本。失败、过期或证据不完整的结论不能用于完成；审核发现的问题也进入同一处理流程。
- R4：看板可逐项查看发现、退回、修改、复验和延期；大记录不再让已有动作消失。不完整证据不能显示为无修复。旧历史只恢复可核对轮次和动作，不补造退回。

# 范围说明
需求/规划/实现返工进入对应阶段；补说明可留在原阶段。needs_human 明确保持待确认。普通建议允许说明原因后延期，阻断问题需复验确认。
