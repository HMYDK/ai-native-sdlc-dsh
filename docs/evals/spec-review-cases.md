## 独立于程序检查的目标

协议测试只验证原文传递、结果校验、复审关联和失败记录。行为评测要回答：审查后 Spec 是否消除了真实遗漏、保持正确边界、没有引入新要求，以及耗费多少轮次、Token 和人工处理。评测正确答案在调用前由需求负责人核对，不能由被评测的 Actor 或审查者自己决定。

## 执行与报告

1. 先固定每例 Source、缺陷/正确 Spec、作者修订或反证和标签。标签材料放在审查者工作区之外，不能依赖“没有拼进 prompt”来声称盲评。
2. 新建处于 SPEC 的任务；不提供新功能实现或最终交付测试结果，避免把终局验证当成前置审查。
3. 首轮检查发现是否真实；修订轮必须通过 `previous_review` / `responses` 回到同一组发现，核对 addressed / withdrawn / open / needs_clarification 的依据。
4. 保留每个实际调用和失败；分别报告发现正确性、误报、遗漏、修订是否消除问题、不必要人工澄清、完成率、调用轮次、Token 和时间。
5. 若比较有无前置审查，用同一原始来源和相同预算约束，独立盲评最终 Spec。先报告逐例结果，不从这组小样本推断总体改善。

SR-03/04/05 是明确标注的受控补充样例，不能计作三个历史 bug。测试桩返回相同标签也不构成模型行为证据。
