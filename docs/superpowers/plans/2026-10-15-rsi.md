# RSI：从真实验证中学习

> **For agentic workers:** Use superpowers:subagent-driven-development. Steps are tracked below; the user has approved implementation. Do not ask again before executing this plan.

**Goal:** 把真实验证的每次尝试留下，并让一个有来源的改进假设能通过实际验证调用得到新旧对照结果。

**Architecture:** `sdlc-verify` 发出可等待的运行事件，`sdlc-rsi` 作为独立 npm + bundle 插件保存记录、分析问题、执行实验。记录使用每次运行独立目录、逐事件文件；已有任务状态机继续管理开发任务。第一版实验只改变附加验证指导文字，固定现有验证器、任务输入、判据和预算，不声称支持任意插件版本热切换。

**Tech Stack:** TypeScript strict、Cordis、真实 ToolRuntime / LocalFileSystem、node:test；运行期文件操作走 ctx.fs 与会话 policy；Git 只读命令用于保留起始代码。

## 已确认的缺口

- 验证器无裁决时提前 return，跳过任务目录落盘。
- verification.json 是最新裁决，无法呈现全部轮次。
- 历史基准中部分用例比较两个固定历史提交，并非当前候选的任务级评测。
- session/event 是通知，不能假装异步回调自动完成落盘。收集器需要受管队列与 flush。

## 首版边界

不自动改用户 profile，不自动采纳候选，不以模型自报通过当真值。实验改变附加指导，任意插件代码版本需要分别部署后另做对照。事实缺失、取消、未完成都保留；历史日志不完整时不会补造配置或结论。
